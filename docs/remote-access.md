# Доступ к Улью из города

Схема: дача (Keenetic Giga, 4G за CGNAT) сама поднимает WireGuard-туннель до городского Keenetic Giant, у которого белый IP. Через этот туннель город видит дачные сети.

| | Дача (Giga) | Город (Giant) |
|---|---|---|
| Интерфейс WireGuard | Wireguard0 «toGiant», 10.10.10.2 | Wireguard1 «toGiga», 10.10.10.1, UDP 51820 |
| Сети | **192.168.10.0/24 дом (Улей 192.168.10.4)**, 172.16.1.0/24 IoT (шершни), 172.16.2.0/24 детская | 192.168.1.0/24 дом, 10.1.30.0/24, 192.168.3.0/24 |

RPi стоит у аккумулятора, в домашней сети дачи, рядом с хабом, где висят остальные устройства на закреплённых адресах. Адрес `192.168.10.4` закреплён за MAC `eth0` RPi на Giga. Адрес `192.168.1.x` не использовать на даче: это городская сеть, и туннель будет вести её трафик в дом.

## 1. Маршруты

Город → дача. На Giant:
- в настройках пира Giga в «Разрешённые подсети» добавить `192.168.10.0/24`;
- «Маршрутизация» → «Добавить маршрут»: сеть `192.168.10.0/24`, интерфейс Wireguard1.

Дача → город (ответы). На Giga:
- в настройках пира Giant в «Разрешённые подсети» добавить `192.168.1.0/24`;
- маршрут: сеть `192.168.1.0/24`, интерфейс Wireguard0.

## 2. Доступ из IoT к Улью

Шершни в IoT-сегменте (172.16.1.0/24) ходят на RPi по адресу `192.168.10.4`. Оба сегмента уже на одном роутере Giga, поэтому маршрут здесь не нужен: это правило доступа между сегментами (политика IoT / межсетевой экран Giga). Keenetic по умолчанию не пускает IoT в домашнюю сеть, поэтому правило разрешает только нужные порты:

| Действие | Источник | Назначение | Протокол / порт | Зачем |
|---|---|---|---|---|
| Разрешить | 172.16.1.0/24 | 192.168.10.4 | TCP, порт назначения 80 | регистрация шершня, загрузка фото (HTTP) |
| Разрешить | 172.16.1.0/24 | 192.168.10.4 | TCP, порт назначения 1883 | MQTT шершней (порт источника любой) |

Это ослабляет изоляцию IoT от дома ровно на эти два порта. Порт источника в правилах всегда «любой»: шершень выбирает его сам. Остальное (SSH, интерфейс по 443) из IoT закрыто.

## 3. Межсетевой экран для города

Keenetic по умолчанию считает WireGuard внешним интерфейсом и не пускает с него входящие соединения. На Giga, «Межсетевой экран» → Wireguard0, добавить правила:

| Действие | Источник | Назначение | Протокол / порт |
|---|---|---|---|
| Разрешить | 192.168.1.0/24 | 192.168.10.4 | TCP 22 (SSH) |
| Разрешить | 192.168.1.0/24 | 192.168.10.4 | TCP 443 (интерфейс) |
| Разрешить | 192.168.1.0/24 | 192.168.10.4 | TCP 80 (сертификат /ca.crt) |

## 4. Проверка из города

```sh
ping 192.168.10.4
ssh kirill@192.168.10.4
```

Интерфейс открывается по `https://192.168.10.4/`. Адрес 192.168.10.4 должен быть в сертификате: это `install.sh --host 192.168.10.4`.

Проверка из IoT: с любого шершня (или ноутбука, подключённого к IoT-сегменту) `curl http://192.168.10.4/healthz` должен вернуть `{"status":"ok"}`.

## 5. Второй путь: Tailscale (по желанию)

Если туннель Keenetic упал или Giga недоступен, Tailscale на самом RPi даёт независимый вход. Он работает через CGNAT и ничего не требует от роутеров:

```sh
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
```

После входа в аккаунт Tailscale RPi доступен с телефона или ноутбука из того же аккаунта по имени `hive`. Ограничение: оператор 4G в режиме белых списков (spec 11.7) режет и этот канал, и сам WireGuard. В таком режиме остаётся только SMS (шаг 17).

## Что не делать

- Не пробрасывать порты Улья в интернет: на даче всё равно CGNAT, а админка не должна торчать наружу (spec 12).
- Не хранить белый IP города в репозитории и документах.
- Не выдавать дачной домашней сети адреса из 192.168.1.0/24.
