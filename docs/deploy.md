# Установка Улья на Raspberry Pi

Спецификация: разделы 3.1 и 13 в [architecture.md](architecture.md). Доступ из города: [remote-access.md](remote-access.md).

## Что получится

На RPi в Docker работают четыре контейнера:

| Контейнер | Что делает | Лимит памяти |
|---|---|---|
| `web` | Caddy: интерфейс по HTTPS, приём фото и регистрация шершней по HTTP | 96 МБ |
| `api` | backend (.NET 10) | 320 МБ |
| `postgres` | PostgreSQL 17 | 448 МБ |
| `mosquitto` | MQTT-брокер с отдельным логином для каждого шершня (dynamic security) | 64 МБ |

Лимиты рассчитаны на RPi 4 с 2 ГБ: контейнерам около 1 ГБ, остальное системе и файловому кешу. Своп сжимается в памяти (zram), на диск он не пишет.

Данные лежат в `/srv/hive` (`pg`, `media`, `mosquitto`, `caddy`, `backups`), настройки и compose-файлы в `/opt/hive`, секреты в `/opt/hive/.env`.

## 1. Система

1. Raspberry Pi Imager → **Raspberry Pi OS Lite (64-bit)**. Нужна именно 64-битная: образы собраны под arm64.
2. В настройках Imager (шестерёнка): имя хоста `hive`, пользователь `kirill`, включить SSH с ключом. Wi-Fi не нужен, RPi подключается кабелем.
3. Записать на SSD/NVMe в USB-боксе и загружаться с него (spec 3.1). На SD-карте PostgreSQL быстро её изнашивает.

## 2. Образы (на ПК)

Нужен запущенный Docker Desktop. Из корня репозитория в Git Bash:

```sh
cd firmware && pio run && cd ..   # прошивки попадут в мастер «Добавить шершня» (необязательно)
deploy/build-images.sh            # → deploy/dist/hive-images-<версия>-arm64.tar.gz
```

Версия образа берётся из git (`git describe`), к ней добавляется `-dirty`, если есть незакоммиченные изменения.

## 3. Установка (подготовка в городе)

RPi включён в городскую сеть, ПК его видит:

```sh
deploy/ship.sh kirill@hive.local --host 172.16.1.2 --rtc
```

- `--host 172.16.1.2` — адрес, который у RPi будет на даче: он сразу попадает в HTTPS-сертификат.
- `--rtc` — если подключён модуль часов DS3231 (адрес 0x68 на I2C).
- `--w1-pin N` — если DS18B20 на плате висит не на GPIO4.

Скрипт копирует файлы, ставит Docker, chrony и zram, включает 1-Wire и I2C, генерирует пароли, спрашивает токен Telegram-бота, загружает образы и запускает Улей. В конце он печатает адрес и одноразовый пароль пользователя `admin`. **После первой установки нужна перезагрузка** (`sudo reboot`): без неё не работают лимиты памяти и 1-Wire.

Повторный запуск `sudo /opt/hive/install.sh` ничего не ломает: пароли остаются, обновляются адреса и настройки.

## 4. Переезд на дачу

1. На Keenetic Giga закрепить за RPi адрес в IoT-сегменте: «Список устройств» → RPi → «Постоянный IP-адрес» `172.16.1.2`. MAC-адрес покажет `ip -br link show eth0`.
2. Подключить RPi кабелем в порт IoT-сегмента и включить.
3. Из города по туннелю (см. [remote-access.md](remote-access.md)) обновить адреса: `ssh kirill@172.16.1.2 sudo /opt/hive/install.sh`.

## 5. Первый вход

- Интерфейс: `https://172.16.1.2/`. Браузер предупредит о сертификате: Caddy выпускает его сам, публичного имени у Улья нет. Чтобы предупреждения не было, один раз установите корневой сертификат `http://172.16.1.2/ca.crt`:
  - Windows: открыть файл → «Установить сертификат» → «Локальный компьютер» → «Доверенные корневые центры сертификации».
  - Android: Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС.
  - iPhone: открыть файл, установить профиль, затем Настройки → Основные → Об этом устройстве → Доверие сертификатам.
- Мастер «Добавить шершня» прошивает платы через Web Serial, а он работает только по HTTPS в Chrome или Edge на компьютере.
- Шершням указывать адрес `http://172.16.1.2`: им нужен обычный HTTP без шифрования, и Caddy пропускает по HTTP только приём фото и регистрацию.

## 6. Самоконтроль Улья

В рое появляется устройство `hive-home`. Оно раз в минуту публикует:

- `temperature` — воздух у платы (DS18B20 на 1-Wire, GPIO4);
- `cpu_temperature` — температура процессора;
- `disk_used_pct` — сколько занято на диске с фото.

Выше порога приходит предупреждение в Telegram (без звука), а когда значение возвращается в норму, приходит информационное сообщение. Пороги по умолчанию: воздух 45 °C (`HIVE_AIR_WARN_C` в `.env`), процессор 75 °C, диск 85 %. Сообщение «в норме» приходит, только когда значение опустится на 3 единицы ниже порога, чтобы на границе уведомления не сыпались каждую минуту.

## 7. Обновление

На ПК: `deploy/build-images.sh`, затем `deploy/ship.sh kirill@172.16.1.2`. Если Улей уже установлен, вызывается `update.sh`. Он делает дамп базы в `/srv/hive/backups`, запускает новую версию и ждёт ответа `/readyz`. Если за 2 минуты ответа нет, он возвращает прежнюю версию и печатает команды для восстановления дампа.

## Полезные команды на RPi

```sh
cd /opt/hive
docker compose ps                 # что запущено
docker compose logs -f api        # логи backend
docker stats --no-stream          # память контейнеров
sudo nano .env && docker compose up -d   # поменять настройки (токен бота и т. п.)
```

Пароль `MQTT_ADMIN_PASSWORD` действует с первого запуска брокера: потом он хранится в `/srv/hive/mosquitto/dynamic-security.json`, и правка `.env` его не меняет.
