# Установка Улья на Raspberry Pi

Спецификация: разделы 3.1 и 13 в [architecture.md](architecture.md). Доступ из города: [remote-access.md](remote-access.md).

## Что получится

На RPi в Docker работают четыре контейнера:

| Контейнер | Что делает | Лимит памяти |
|---|---|---|
| `web` | Caddy: интерфейс по HTTPS, приём фото и регистрация шершней по HTTP | 96 МБ |
| `api` | backend (.NET 10) | 320 МБ |
| `postgres` | PostgreSQL 17 | 448 МБ |
| `mosquitto` | MQTT-брокер с отдельным логином для каждого шершня (dynamic security) | 64 МБ |

Лимиты рассчитаны на RPi 4 с 2 ГБ: контейнерам около 1 ГБ, остальное системе и файловому кешу. Своп сжимается в памяти (zram), на диск он не пишет.

Данные лежат в `/srv/hive` (`pg`, `media`, `mosquitto`, `caddy`, `backups`), настройки и compose-файлы в `/opt/hive`, секреты в `/opt/hive/.env`.

## 1. Система на RPi

1. Скачай **Raspberry Pi Imager** с raspberrypi.com.
2. «Выбрать ОС» → **Raspberry Pi OS (other)** → **Raspberry Pi OS Lite (64-bit)**. Именно 64-bit.
3. «Выбрать накопитель» → свой SSD или USB-диск.
4. «Далее» → «Изменить настройки»:
   - имя хоста: `hive` (или оставь `rpi`, тогда адрес `kirill@192.168.10.4` всё равно работает);
   - пользователь `kirill` и пароль;
   - включить SSH, с паролем.
5. Записать и загрузить RPi с этого диска (на SD-карте PostgreSQL быстро изнашивается).

## 2. Образы на ПК (одна команда)

На ПК, в Git Bash, из папки репозитория (`F:\Docs\Git\Village_swarm`), при запущенном Docker Desktop:

```bash
bash deploy/build-images.sh linux/arm64
```

Команда собирает два образа под RPi: **backend** (`village-swarm-api`, .NET) и **frontend** (`village-swarm-web`, интерфейс на Caddy). `make` на Windows не нужен и кладёт архив в `deploy/dist/`. Первый раз это занимает несколько минут. Больше на ПК ничего делать не нужно. Прошивки шершней сюда не относятся.

## 3. Установка (подготовка в городе)

Нужны: RPi включена в сеть с интернетом, ПК видит её по SSH. Адрес `192.168.10.4` должен быть закреплён на Giga (см. [remote-access.md](remote-access.md)), либо используй адрес, который RPi сейчас получила.

```bash
bash deploy/ship.sh kirill@192.168.10.4 --host 192.168.10.4 --rtc
```

- `PI=…` — пользователь и адрес RPi.
- `--host 192.168.10.4` — адрес, по которому будут открывать Улей; попадает в сертификат.
- `--rtc` — только если подключён модуль часов DS3231.
- `--w1-pin N` — если DS18B20 на другом GPIO, чем 4.

Что происходит: `ship` копирует архив и файлы установки на RPi и запускает там `install.sh`. Тот ставит Docker, настраивает систему, генерирует пароли, спрашивает токен Telegram-бота (можно пропустить Enter) и запускает стек. В конце печатает адрес и пароль `admin`. После первой установки: `sudo reboot`.

Повторный запуск той же команды обновляет Улей, а не ставит заново.

- `--host 192.168.10.4` — адрес RPi в домашней сети дачи: он сразу попадает в HTTPS-сертификат.
- `--rtc` — если подключён модуль часов DS3231 (адрес 0x68 на I2C).
- `--w1-pin N` — если DS18B20 на плате висит не на GPIO4.

Скрипт копирует файлы, ставит Docker, chrony и zram, включает 1-Wire и I2C, генерирует пароли, спрашивает токен Telegram-бота, загружает образы и запускает Улей. В конце он печатает адрес и одноразовый пароль пользователя `admin`. **После первой установки нужна перезагрузка** (`sudo reboot`): без неё не работают лимиты памяти и 1-Wire.

Повторный запуск `sudo /opt/hive/install.sh` ничего не ломает: пароли остаются, обновляются адреса и настройки.

## Одной кнопкой

`deploy\deploy.bat` (двойной клик или из командной строки) собирает прошивки шершней (PlatformIO, для обновления по воздуху), затем образы backend и frontend и доставляет их на RPi: то есть шаги 2 и 3 вместе. Прошивки можно пропустить: `set SKIP_FIRMWARE=1` перед запуском. Он работает через WSL (Ubuntu с Docker Desktop):

```
deploy\deploy.bat                        # kirill@192.168.10.4
deploy\deploy.bat kirill@192.168.10.4 --rtc    # с часами DS3231 при первой установке
```

В конце окно ждёт нажатия клавиши, чтобы можно было прочитать вывод. Пароль RPi (и `sudo`) спросит сам скрипт.

## 4. Переезд на дачу

1. RPi подключается кабелем к дачному Giga в обычный порт домашней сети (рядом с аккумулятором, там же хаб с остальными устройствами).
2. На Keenetic Giga закрепить за RPi адрес в домашней сети: «Список устройств» → RPi → «Постоянный IP-адрес» `192.168.10.4`. MAC `eth0` покажет `ip -br link show eth0`.
3. Выключить Wi-Fi на RPi (`sudo nmcli radio wifi off`), чтобы она ходила только по кабелю.
4. Из города по туннелю (см. [remote-access.md](remote-access.md)) обновить адреса: `ssh kirill@192.168.10.4 sudo /opt/hive/install.sh --host 192.168.10.4`.

## 5. Первый вход

- Интерфейс: `https://192.168.10.4/`. Браузер предупредит о сертификате: Caddy выпускает его сам, публичного имени у Улья нет. Чтобы предупреждения не было, один раз установите корневой сертификат `http://192.168.10.4/ca.crt`:
  - Windows: открыть файл → «Установить сертификат» → «Локальный компьютер» → «Доверенные корневые центры сертификации».
  - Android: Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС.
  - iPhone: открыть файл, установить профиль, затем Настройки → Основные → Об этом устройстве → Доверие сертификатам.
  - Firefox (у него своё хранилище): Настройки → Приватность и защита → Сертификаты → Просмотр сертификатов → Центры сертификации → Импортировать, отметить «Доверять при идентификации веб-сайтов». Старое исключение для Улья на вкладке «Серверы» лучше удалить.
  - Те же шаги есть в интерфейсе: Настройки → «Сертификат Улья».
- Мастер «Добавить шершня» прошивает платы через Web Serial, а он работает только по HTTPS в Chrome или Edge на компьютере.
- Шершням указывать адрес `http://192.168.10.4`: им нужен обычный HTTP без шифрования, и Caddy пропускает по HTTP только приём фото и регистрацию. Шершни стоят в IoT-сегменте, поэтому для них открыт доступ из IoT к RPi (см. [remote-access.md](remote-access.md)).

## 6. Самоконтроль Улья

В рое появляется устройство `hive-home`. Оно раз в минуту публикует:

- `temperature` — воздух у платы (DS18B20 на 1-Wire, GPIO4);
- `cpu_temperature` — температура процессора;
- `disk_used_pct` — сколько занято на диске с фото.

Выше порога приходит предупреждение в Telegram (без звука), а когда значение возвращается в норму, приходит информационное сообщение. Пороги по умолчанию: воздух 45 °C (`HIVE_AIR_WARN_C` в `.env`), процессор 75 °C, диск 85 %. Сообщение «в норме» приходит, только когда значение опустится на 3 единицы ниже порога, чтобы на границе уведомления не сыпались каждую минуту.

Ещё Улей следит за шершнями: если шершень не на связи 15 минут (`Hive__OfflineWatch__Minutes`), приходит предупреждение в Telegram, а когда он вернулся, запись в ленте. Короткие пропадания (перезагрузка, сбой Wi-Fi) не беспокоят. Спящие на батарее шершни считаются потерянными только после нескольких пропущенных пробуждений.

## 7. Бэкапы

Контейнер `backup` каждую ночь делает дамп базы, раз в неделю проверяет, что дамп восстанавливается, и пишет результат в **Настройки → Бэкапы**. Если свежего дампа нет больше 36 часов, приходит сообщение в Telegram. Копию вне Улья (на другой диск или в облако) нужно настроить отдельно: `docs/restore.md`, там же восстановление.

### Диск и хранение

Каждую ночь в 4:00 (после бэкапа) Улей наводит порядок. Сроки по умолчанию (`Retention__...` в `.env`, если нужно изменить):

| Что | Сколько хранится |
|---|---|
| Фото тревог (alarm и выше) | 365 дней |
| Остальные фото и снимки | 30 дней |
| Фото с пометкой «не удалять» | навсегда |
| Показания датчиков | 90 дней подробно (месяцы целиком), потом навсегда по часам: графики за год работают |
| Здоровье шершней / журналы | 14 / 30 дней |
| События | навсегда |

Если диск занят больше чем на 85% (проверка каждые 15 минут), Улей сам удаляет старое по шагам: сначала обычные фото (старше 7 дней, потом 1 дня, потом любые), затем кадры таймлапса, и только потом фото тревог старше 180, затем 90 дней. Каждый шаг удаляет самые старые подходящие фото и останавливается, как только диск опустится до 80%: если диск забит не фото (база, копии), все фото разом не пропадут, а предупреждение «диск почти полон» останется. Фото тревог моложе 30 дней и фото с пометкой «не удалять» не удаляются никогда. После такой очистки приходит сообщение в Telegram. Состояние диска и последняя очистка: **Настройки → Диск и хранение**.

### Сменить Wi-Fi у работающих шершней

В **Настройки → Wi-Fi для шершней** впишите новую сеть и пароль, сохраните и выберите способ. Экран объясняет оба прямо перед кнопкой и пишет, что именно произойдёт с отмеченными платами.

**1. Подготовить запасную сеть (рекомендуется).** Ничего не переключается и не перезагружается: шершень остаётся на нынешней сети и запоминает новую про запас. Порядок:
1. Отметьте шершней и нажмите «Подготовить запасную сеть».
2. Дождитесь в «Событиях» у каждого «запасная сеть сохранена».
3. Смените имя или пароль на роутере.
4. Шершни, не сумев войти в старую сеть, сами пробуют запасную. Вошёл и связался с Ульем: она становится основной. Спящие платы пробуют по очереди при каждом пробуждении, бодрствующие через 45 секунд без связи.

Так можно сменить и пароль той же сети.

**2. Переключить сейчас (проверка).** Шершень сразу перезагружается и пробует новую сеть. Вышел на связь с Ульем: она основная, прежняя остаётся запасной. Не вышел за минуту: сам возвращается на прежнюю и сообщает об этом. Нужна новая сеть, которая уже работает рядом со старой (второе имя на роутере). Для пароля той же сети не подходит.

- Пароль уходит шершню в команде и нигде не хранится: в журнале команд вместо него `***`, в мониторе MQTT тоже.
- Шершни **не на связи** и **спящие** (глубокий сон) команду не получают: в списке они отключены с пояснением. Повторите, когда проснутся (или включите режим «не спит» на время).
- «Запасная сеть» требует прошивки с возможностью `wifi.stage`: шершни со старой прошивкой в этом режиме не выбираются. Обновите их или прошейте по USB.
- Сеть, где есть Wi-Fi, но нет Улья, шершня не держит: на запасной он ждёт брокер 2 минуты, на основной 5, потом пробует другую сеть. Так шершень не застрянет на старой гостевой сети после перезагрузки роутера.
- Ненужную запасную сеть (например, старую временную) можно стереть по воздуху: страница шершня → «Забыть запасную сеть» (нужна прошивка с `wifi.forget`).
- Старый роутер или пароль меняйте только после того, как у всех шершней в «Событиях» «запасная сеть сохранена» (или «теперь в сети ...»).
- Если плата пропала, её возвращает консоль по USB: Рой → «Консоль по USB» (`docs/rescue.md`).

## 8. Обновление

На ПК: `bash deploy/build-images.sh linux/arm64`, затем `bash deploy/ship.sh kirill@192.168.10.4 --host 192.168.10.4`. Если Улей уже установлен, вызывается `update.sh`. Он делает дамп базы в `/srv/hive/backups`, запускает новую версию и ждёт ответа `/readyz`. Если за 2 минуты ответа нет, он возвращает прежнюю версию и печатает команды для восстановления дампа. После удачного обновления он удаляет образы старых версий Улья, оставляя текущую и предыдущую: каждая сборка весит сотни мегабайт, и без этого SD-карта забивается версиями.

## Полезные команды на RPi

```sh
cd /opt/hive
docker compose ps                 # что запущено
docker compose logs -f api        # логи backend
docker stats --no-stream          # память контейнеров
sudo nano .env && docker compose up -d   # поменять настройки (токен бота и т. п.)
```

Пароль `MQTT_ADMIN_PASSWORD` действует с первого запуска брокера: потом он хранится в `/srv/hive/mosquitto/dynamic-security.json`, и правка `.env` его не меняет.
